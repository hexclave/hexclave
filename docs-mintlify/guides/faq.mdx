# FAQ

## Languages & Frameworks

<AccordionGroup>
  <Accordion title="What languages are supported?">
    For frontends, Stack supports TypeScript and JavaScript, and also has a Swift SDK in public beta. For backends, Stack has a flexible [REST API](/api/overview) that can be used with any language or framework.
  </Accordion>

  <Accordion title="Can I use Stack with other JavaScript frameworks, like Astro or Angular?">
    Yes! You can use our vanilla JavaScript SDK, or, if the framework is React-based, our React SDK.
  </Accordion>
</AccordionGroup>

## Product

<AccordionGroup>
  <Accordion title="How do you compare to `<X>`?">
    Ask yourself about `<X>`:

    - Is `<X>` open-source?
    - Is `<X>` developer-friendly, well-documented, and lets you get started in minutes?
    - Besides authentication, does `<X>` also do authorization and user management (see feature list below)?

    If you answered "no" to any of these questions, then that's how Hexclave is different from `<X>`.
  </Accordion>

  <Accordion title="Can I migrate my existing userbase to Hexclave?">
    Yes. Create users with the [server users API](/api/server/users/create-user) or `hexclaveServerApp.createUser()`. The SDK accepts `password`. The REST API also accepts `password_hash` if you already have a bcrypt hash in Modular Crypt Format (for example `$2a$10$…`). Do not send both.
  </Accordion>

  <Accordion title="How do I make sign-up invite-only?">
    Set `auth.allowSignUp` to `false` and create users with the server API. Existing users can still sign in; new OAuth or password sign-ups cannot create an account. See [Sign-up rules](/guides/apps/authentication/sign-up-rules#invite-only-or-an-existing-directory).
  </Accordion>
</AccordionGroup>
